## 2. 主要原因：高误差位置先被冻结，低收益位置继续加密

`src/core/adaptive-mesh.js` 的 `createAdaptiveRefinementPolicy()` 只根据初始网格的中位单元面积建立一次策略：

- 普通最小面积为 `baseArea / 4096`。
- 点力中心目标为 `baseArea / 1024`，外围目标上限为 `baseArea / 64`。
- 点力保护半径为 `2 * sqrt(baseArea)`，尺寸下限通过指数函数向外衰减。
- `markAdaptiveElements()` 先排除 `area / 4 <= floor` 的单元，再对剩余单元做误差排序、异常值限幅、50% 累计标记和背景补充。

因此，报告误差仍计入被冻结单元，而后续加密只能选择其他位置。
点力保护也不是严格局限在半径以内；其衰减范围可能覆盖另一处固定边端点。

用保存的网格、C++ 应力结果重新计算相同 ZZ 指标，并复现同种子的初始网格策略，得到：

| 工况 | 被尺寸下限冻结的误差指标能量占比 | 其中仅由点力保护范围额外冻结 | 下一轮选中单元覆盖的误差指标能量 |
| --- | ---: | ---: | ---: |
| g1-c1 | 99.68% | 65.41% | 0.16% |
| g1-c2 | 88.40% | 0.94% | 5.80% |
| g2-c1 | 99.35% | 3.10% | 0.32% |
| g3-c2 | 99.68% | 99.59% | 0.16% |

这里的“能量占比”是各单元 ZZ 指标平方之和的占比，并非真实误差认证。

以几何尺度的 3% 为邻域半径，7 个工况有约 85%–97% 的误差指标能量位于固定支撑端点附近；另一个工况 g2-c1 约 89% 位于点力附近。
材料界面的恢复应力已按材料和区域分组，代码没有跨材料直接平均；目前没有证据把材料混合平均列为主因。

平台现象十分明显：g1-c1 从 4227 节点、14.55% 误差增长到 22214 节点，误差仅降到 13.79%；g3-c2 从 5760 节点、19.84% 增长到 24376 节点，误差仅降到 19.38%。

## 3. 第二个原因：整轮超过预算就丢弃

`python_machine_learning/generation-core.cjs` 先建立完整候选加密网格，再检查节点数。
只要候选超过 30000，就立即保留上一张已解网格并退出；不会缩小标记集合、重新尝试较小步长。
因此，22214、20322、21229 等节点数都可能因下一轮过大而停止，剩余预算无法用于最有价值的位置。

这项优化能更好利用预算，但若不先解决高误差单元冻结，只填满节点预算仍可能收益很低。

## 4. 有限的真实对照求解

采用原批次已保存的几何、材料、载荷、支撑和最后求解状态，保持原有 C++ 求解器与 ZZ 定义。
每轮直接按未限幅 ZZ 指标排序，选择最高的 800 个有效单元；暂时绕过原尺寸保护，仍检查 30000 节点预算和退化单元限制。
对照仅在进程内进行，不覆盖原始文件，也不自动入库。

g1-c1 的结果：

| 补充加密轮数 | 节点数 | ZZ 误差 |
| --- | ---: | ---: |
| 0 | 22214 | 13.79% |
| 1 | 23617 | 9.87% |
| 2 | 25025 | 7.17% |
| 3 | 26560 | 5.32% |

增加约 19.6% 节点后，报告误差下降约 61.4%。该工况仍未达到 5%，不能计为达标。
另一个临界工况 g1-c2 从 22099 节点、5.76%，只补充一轮到 23553 节点就降到 4.44%，达到原 5% 门槛；节点增加约 6.6%。
这支持“修正标记和尺寸保护，比在原策略下继续全局增加节点更有价值”的判断。
直接取消尺寸保护只是定位问题的实验，不适合作为最终生产策略：点载荷和固定边端点的奇异性仍需受控处理。

## 5. 建议开发顺序

### 优先级一：修正加密策略，保持原精度判据

1. 将普通尺寸下限、点力保护、支撑端点和几何角点分别处理。点力保护应有明确、局部的作用范围，避免阻断附近独立支撑热点。
2. 每轮记录被冻结的误差指标能量比例。当误差明显超标且大部分误差被下限冻结时，进入有限次数的热点补救，逐级放宽相关局部尺寸下限。
3. 限幅仅用于防止奇异点垄断预算，同时给原始高误差热点保留可控份额。不能只在低误差剩余集合中完成累计标记。
4. 候选超过节点预算时，按误差收益缩小标记集合并有界重试；计入共形闭合和 Triangle 质量节点的实际开销。
5. 用连续轮次误差下降幅度和冻结比例识别平台。可修复的平台先补救，无法修复时以明确原因停止，避免继续堆积低收益节点。
6. 节点预算、时间限制或补救失败时，继续保留最后一份已成功求解的网格及对应结果，不能错配新网格与旧误差。

主要修改位置是 `src/core/adaptive-mesh.js` 和 `python_machine_learning/generation-core.cjs`。
普通计算与训练生成共用前者，需要明确选项边界并验证原有自适应行为。

### 优先级二：改善随机工况分布

- 当前默认勾选的每种载荷都会同时出现，并非在三种载荷之间抽样。增加工况类型配额，使分布载荷、体力、点载荷及组合分别有覆盖。
- 提供物理上明确的有限宽度加载选项，记录加载宽度并保持合力、合矩；它会改变局部物理问题，应生成新的工况，不能冒充原点载荷的同一份标签。
- 支撑按连续边界片段采样，检查长度、端点角度及其与点力、材料交点的距离，避免频繁形成极短夹持段。固定端仍可能产生奇异性，不能保证通过选长边彻底消除。
- 几何增加短边、狭窄连接、尖角和局部净间距检查；材料按刚度比、几何按复杂度分层。
- 保留困难工况配额和独立验证集，避免只靠筛除困难样本提高通过率而损害泛化范围。

主要修改位置是 `python_machine_learning/random_geometry.py` 和生成参数界面。

### 优先级三：补齐可观测性与数据分级

- 在生成记录中分别显示求解成功率、目标误差达标率、入库数量和单位时间达标数。
- 每轮记录原始/限幅误差、标记数量、冻结数量及误差占比、节点增量、候选超预算数量、重试和补救原因。
- 达标参考继续走严格自动导入；有效但未达目标的参考可按实际误差分级使用。
  现有训练特征已经包含实际参考误差，手动导入也保存该误差，因此这些样本可供相应精度条件训练，但不能当成 5% 标签。
- 不建议通过隐藏热点误差、把 10% 参考标为 5%，或只修改停止原因来提高表面通过率。
- 若未来引入奇异邻域之外的误差指标，应独立命名、版本化，并同步修改训练条件、验证目标和历史兼容逻辑，不能继续沿用全域 5% 的含义。

## 6. 验证方案与边界

先复现这 8 个工况，再用事先固定种子的 30–50 个独立工况比较旧、新策略。
保持目标 5%、节点上限和时间预算一致，报告达标数、耗时、每小时达标数、节点数，以及按点力/支撑/材料/几何复杂度分组的结果。
另用未参与调整的种子检查效果，避免只适配已有几个模型。

回归检查重点：误差定义保持一致、载荷合力和合矩、材料界面和孔洞共形、支撑有效性、网格与结果对应、预算重试有界、暂停恢复与导入门槛。
最终通过率必须通过批量真实求解确认；当前对照不足以承诺具体通过率。

奇异性原理参考厂商一手资料：[COMSOL：Singular Loads](https://doc.comsol.com/6.4/doc/com.comsol.help.sme/sme_ug_modeling.05.071.html)、[COMSOL：Singularities in Finite Element Models](https://www.comsol.com/blogs/singularities-in-finite-element-models-dealing-with-red-spots)。后者也讨论了约束端点的奇异性。
