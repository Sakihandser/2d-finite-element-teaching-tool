# GPU 自动切换阈值基准（2026-10-13）

## 结论与默认策略

**本机当前实现没有测到 GPU 优于 CPU 的单元数量交叉点。** 撤销此前未经验证的 131072 单元阈值；默认 `auto` 保持 CPU，避免自适应细化到大规模后切换到更慢的路径。GPU 后端保留用于验证和后续优化。

本结论覆盖本机所测范围及当前实现，不能外推为所有显卡或任意规模永远不会受益。其他硬件/优化后的后端必须重新测试；有稳定交叉点后，通过正整数 `FEM_GPU_MIN_ELEMENTS` 设置自动切换阈值。

## 硬件和方法

- CPU：Intel Core i9-13900HX；内存约 32 GB；CPU 单元计算使用 8 个 OpenMP 线程。
- GPU：NVIDIA GeForce RTX 4070 Laptop GPU；Windows 驱动版本 `32.0.16.1047`；OpenCL FP64。
- 使用 Release/x64 完整 native 求解器，CPU 和 GPU 使用相同材料、载荷、网格和 Eigen LDLT 求解器。
- 每个规模先各预热一次，再交替先后顺序做五组 CPU/GPU 求解，报告中位数；未并行运行其他基准。
- 计时包含 native 进程启动、输入/结果二进制管道、完整力学求解和写性能日志；预先编码输入，计时不包括 JavaScript 编解码、浏览器、网格生成和 ZZ 估计。
- 逐项验证所有位移、应变、应力、安全码及结果编号。相对容差 `1e-8`，应力绝对容差 `1e-5 Pa`，其余绝对容差 `1e-12`；所有安全码一致。没有将回退 CPU 当作 GPU 测试。
- 规模扫描使用非均匀坐标、两种材料的矩形板。逐个增大网格，每次都创建新的 native 进程，这与现有自适应工作流的求解进程生命周期一致。

这是 native 路径的上限探索。最大网格通过直接二进制输入测试，不是从浏览器 HTTP 请求提交；现有服务器另外有 50 MB JSON 请求和 100 MB 二进制结果限制。所有测例的结果均低于 100 MB。

| 131,072 | 1.214 | 2.062 | 0 / 5 |

| 524,288 | 10.270 | 11.757 | 0 / 5 |
| 991,232 | 29.071 | 31.121 | 0 / 5 |

最大规模 GPU 仍慢约 7.1%。将同一组编号的七个逐渐增大的求解耗时累计，再取五组中位数：CPU **45.159 秒**，GPU **52.888 秒**。该累计反映规模增长序列，不替代下面的真实局部自适应测例。

预设阈值判断规则：至少三个连续测点 GPU 中位数快 10% 以上，且各测点至少赢得五组中的四组，再在首次稳定获益的区间加密测试、选取阈值。此次所有测点都不满足，因此没有继续围绕不存在的交叉点插值，也没有把最后一个测点当作阈值。

原始每次计时、阶段耗时、日志位置、数值误差和二进制 SHA256 见 [gpu-compute-sweep.json](benchmarks/gpu-compute-sweep.json)。

## 实际自适应细化序列

使用已有回归测例的椭圆狭缝孔洞、远场牵引和集中力，调用现有 ZZ 误差估计、bulk 标记及 Triangle 局部细化，生成初始网格加八轮细化的九个模型快照。先由 CPU 生成一组真实网格轨迹，再固定这些快照，避免 CPU/GPU 舍入差异改变标记集合后比较不同网格。

两种后端对相同九个模型依次求解；预热后交替顺序重复五组，并逐项验证结果。累计计时包含这九轮求解、IPC 和性能日志读取，不包括冻结轨迹前的 ZZ/细化计算。这些 JavaScript/WASM 工作在两条路径中都继续使用 CPU。

实际单元数依次为 **308 → 480 → 786 → 1378 → 3082 → 6582 → 8628 → 12402 → 19332**。九次求解的累计中位数为 CPU **0.516 秒**、GPU **3.045 秒**，GPU 慢约 **5.9 倍**；五组都是 CPU 更快。细化后的集中力区域和孔洞拓扑来自现有算法，不是把同一个均匀网格机械重复九次。

每轮网格规模、ZZ 估计误差、原始阶段耗时及五组累计时间见 [gpu-adaptive-sequence.json](benchmarks/gpu-adaptive-sequence.json)。

## 为什么没有自动切换点

当前 GPU 后端只计算单元刚度和应变应力。CPU 已使用固定尺寸 Eigen 运算和 OpenMP，这两个阶段本来就很短；GPU 路径增加数据打包、传输、回读和转换。

主要耗时的全局稀疏矩阵 LDLT 分解在两条路径中都由 CPU 执行。例如 991232 单元时，CPU 分解中位数约 **26.77 秒**，CPU 单元刚度和应变应力合计约 **38.9 ms**。GPU 没有加速这 26.77 秒。因此规模增大后，两种完整求解耗时比值趋近，而不是已经出现 GPU 获益。

针对自适应反复求解，后续重点应是持久求解进程、减少输入/结果转换，以及单独验证 GPU 稀疏求解器和预条件方法。网格细化改变连接关系时，不能直接复用旧的数值分解；采用迭代 GPU 求解器也需要重新检验残差、刚体模态、材料跨度和病态网格。仅增加单元数阈值不会解决当前瓶颈。

## 复现

先编译 Release/x64，然后串行运行以下命令，不要同时运行多个性能基准：

```powershell
.\node-v24.21.0-win-x64\node.exe scripts/benchmark-gpu-compute.cjs
.\scripts/benchmark-gpu-elements.ps1
.\node-v24.21.0-win-x64\node.exe scripts/benchmark-adaptive-gpu.cjs
```

`benchmark-gpu-compute.cjs` 支持 `--divisions=32,64,128,...`、`--repeats=5`、`--output=...`；单元数为 `2 * divisions²`。只有全部求解和数值校验通过，报告才标记 `completed=true`。专项 C++ 程序需要 Visual Studio C++ 工具和现有 Eigen 头文件，编译产物放在被忽略的 Debug 子目录；它不会替换正式求解器。

设置方式见 [GPU_COMPUTE.md](GPU_COMPUTE.md)：默认保持 `FEM_COMPUTE=auto` 即可，本机不设置 `FEM_GPU_MIN_ELEMENTS`。强制测试 GPU 时使用 `FEM_COMPUTE=gpu`；驱动或 GPU 不可用仍回退 CPU。
