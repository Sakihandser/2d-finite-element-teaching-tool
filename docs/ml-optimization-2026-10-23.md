# 神经网络训练与预测优化（2026-10-23）

## 诊断

本机运行时缓存选择 CUDA / RTX 4070 Laptop，实际执行也已验证 CUDA。训练和预测中的网络、图张量都放到该设备；几何处理、特征构建和 Triangle WASM 网格细化仍在 CPU 执行。

对平台期记录的最新检查点抽查六个训练工况，预测修正量 `prediction-current` 的标准差约为 1e-7，输入编码层梯度范数约为 1e-10。网络基本只输出统一尺寸偏移，未学到空间变化。该观察解释了为什么继续添加数据或降低学习率仍然容易停滞；它不是对所有平台期原因的排除性证明。

## 实现

- 新训练使用结构 v2：逐特征标准化、归一化前置的残差消息传递、按深度缩放残差，以及直接进入解码器的局部特征通路。标准化统计只由训练图计算，随权重保存，续训保持不变。
- 结构 v1 检查点（包括没有 `architecture` 字段的旧记录）保持原结构加载，支持预测与续训。要使用新结构，应点击“开始新训练”；续训旧检查点不会自动转换结构。
- 增加常量尺寸修正退化诊断，区别于普通学习率平台期。
- 将粗图数量提前在 CPU 计算，避免前向中的 `pool.max().item()` 同步；CUDA 训练图使用最多 256 MiB 的 LRU 缓存，减少重复传输。
- 每次预测只启动一个 Triangle 进程；场景保留在该进程内，轮间仅传递尺寸标记和紧凑网格，最终取回完整场景。推理禁用自动求导。
- 细化前按节点预算规划标记，并限制 Triangle 的附加质量节点，保留细化后的预算校验。
- 预测结果显示实际推理设备及检查点加载、基础网格、图构建、网络、细化和总耗时；下载 JSON 保存设备与阶段耗时。

## 真实数据短程对照

对照实验不会写入原模型或数据。两种结构均从头初始化，宽度 64、6 层、AdamW、学习率 0.001、相同随机种子和输入顺序；比较使用相同损失函数。该脚本逐图更新，未使用服务中的几何组梯度权重，属于网络结构的短程对照，并非完整训练任务的重演。

全量划分：76 个训练工况 / 31 个训练几何，24 个验证工况 / 9 个验证几何，228 张训练图，10 轮：

| 指标 | v1 | v2 |
|---|---:|---:|
| 初始训练损失 | 0.4665 | 0.4665 |
| 第 10 轮训练损失 | 0.2035 | 0.08640 |
| 第 5 轮验证损失 | 0.2074 | 0.1928 |
| 第 10 轮验证损失 | 0.2058 | 0.2479 |
| 最佳验证损失对应轮数 | 8 | 2 |

新结构能显著降低训练拟合误差，但验证曲线仍可能反弹。不能声称最终轮次验证精度已改善，也不能把标签损失视为有限元真实误差。应使用独立验证集、最佳验证检查点与已有学习率/早停策略，最后进行有限元验算。12 工况的小样本探索实验同样显示新结构拟合更快但可能过拟合；该探索实验仅固定初始化种子，未单独固定两种结构的数据打乱顺序，完整划分对照则使用独立的同种子打乱器。

实现中的禁用推理求导、减少 CPU/GPU 同步与重复数据传输也参照 [PyTorch 性能调优指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)。具体性能结论以本项目上述测量为准。

数据见 `ml-benchmark-full.json` 和 `ml-benchmark.json`。复现命令（分支根目录，run 使用本机现有记录 ID）：

```powershell
python_machine_learning/.venv/Scripts/python.exe scripts/benchmark-ml.py --run <记录ID> --epochs 10 --cases 100 --output docs/ml-benchmark-full.json
```

## 预测耗时

对同一实际几何、同一旧检查点、4 轮上限和 20,000 节点预算的单次测量：旧流程约 33.52 秒，新流程约 17.43 秒。新流程网络累计约 0.18 秒、图构建约 1.02 秒、CPU 细化约 10.99 秒，其余包括基础网格、最终场景传输/保存及进程收尾。

两者预算处理行为不同：旧流程丢弃超预算候选后返回 12,476 节点，新流程预先规划后返回 20,000 节点。因此这是同一输入和预算下的端到端案例，不是相同输出网格的严格速度基准，也不是重复测量平均值。主要瓶颈仍是 CPU 网格处理；换用 GPU 运行神经网络本身不能消除这部分等待。数据见 `ml-prediction-benchmark.json`。

## 使用

重启程序以加载更新的 Python 服务和前端；保留旧训练记录，在现有训练/验证划分上开始新训练。原训练数据、模型权重和训练进度未被这次对照实验改写。

验证：80 项 Python 测试、完整 JavaScript 测试集，以及真实 CUDA v2 训练/保存/恢复自检通过。新增测试覆盖空间目标拟合、旧结构检查点恢复、验证集不参与标准化、同一进程连续细化的预算/材料/面积保持及进程收尾。
