# 夜间无人值守训练

现有自适应策略负责过拟合、平台期、最佳模型选择及早停。本次增加运行保护与按需读图，适用于保持程序运行的夜间训练。

## 自动处理范围

| 情况 | 处理 |
|---|---|
| 过拟合、平台期 | 自动恢复最佳模型、降学习率；过拟合时加强正则化；按设置限制尝试次数 |
| 样本很多 | 按需读取工况，CPU 训练图缓存上限 256 MiB；CUDA 图缓存上限 256 MiB |
| 保存时文件暂时不可访问 | 每项保存操作最多尝试 3 次，保留此前完整检查点 |
| 训练损失或梯度非有限 | 从数值有效的完整检查点恢复，学习率降至异常前的 1/4 后重试 |
| CUDA 显存不足 | 从完整检查点恢复到 CPU 继续，界面显示实际 CPU 设备 |
| Windows 自动空闲休眠 | 训练期间请求保持系统唤醒，屏幕仍可关闭；结束、暂停或失败时解除 |
| 反复异常、坏数据、持续磁盘故障等 | 停止并显示错误，保留最近完整检查点，等待人工处理 |

运行异常最多自动恢复 2 次，次数随检查点保存；显存不足回退 CPU 最多一次。过拟合控制的重试次数与运行异常恢复次数分别计数。人工暂停不触发异常重试，也不会重置已有次数。

CUDA 回退 CPU 的决定随检查点保存；重启后恢复这条记录继续使用 CPU，避免立刻重新触发同一显存问题。CPU 训练可能显著变慢。遇到驱动崩溃、进程被杀、内存耗尽导致系统终止等情况，当前进程无法自行执行恢复逻辑。

CPU 缓存上限约束的是缓存张量，不是整个程序的内存。读取一个工况时会载入该工况的图；单个超大工况、模型、梯度、优化器和临时张量仍会额外占用内存。不能把 256 MiB 理解为整个训练进程的内存上限。标准化仍需顺序扫描训练图一次。

## 晚上使用

1. 重启程序加载更新，选择已有记录或开始新训练。
2. 保留独立验证集，勾选“自适应训练策略”和“夜间无人值守保护”。
3. 设置足够的训练轮数、保留自动保存间隔，然后开始/继续训练。
4. 接通电源、保持训练服务运行。可以锁屏或熄屏；不要主动休眠、关机。合盖是否休眠取决于系统电源设置。
5. 达到验证收敛、重试预算或轮数上限时，程序会自动结束并选择最佳模型，不会为了填满一晚而持续拟合。

唤醒请求仅防止自动空闲休眠，不能阻止用户主动休眠或覆盖所有合盖政策，见 [Microsoft SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)。断电或系统重启后，已写入的检查点可以手动继续，但本次没有安装开机服务或实现进程崩溃后自动重启。尚未成功保存的更新可能丢失。

## 验证

测试覆盖按需加载和缓存淘汰、临时文件占用重试、持续写入失败停止、数值异常恢复、运行恢复次数上限、CPU 回退与跨重启保持、Windows 防休眠请求的异常清理。

另外，在实际 CUDA 网络训练中注入一次非有限损失异常和一次 CUDA OOM 异常，分别验证恢复后继续 CUDA 训练、切换 CPU 训练，两种情况均从完整检查点完成剩余 8 步。OOM 使用故障注入，未通过耗尽整张显卡显存来测试。尚未进行连续整晚、多万工况的负载验证。
