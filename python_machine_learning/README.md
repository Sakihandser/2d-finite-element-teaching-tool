# 图神经网络训练与节点预测

在**机器学习分支**目录启动 `RUN_PROGRAM.bat`，打开顶部 **神经网络训练** 标签页。
训练在独立 Python 进程运行，默认自动选择通过实际图网络训练自检的 GPU，无可用 GPU 时使用 CPU；切换标签页不停止训练。
已加入独立的 CPU / DirectML 环境，保留现有 NVIDIA CUDA 环境。
GNNv1.1 完整 Release 附件已包含 Python 和全部运行环境，解压后可直接启动，无需另行下载配置。
安装、跨厂商支持范围与测试结果见 [通用机器学习运行环境](RUNTIME_SETUP.md)。

训练页新增 **自动生成训练数据**：随机拼装合并图形、切割材料区域、挖孔、施加支撑和载荷，
通过现有 Triangle/C++/ZZ 流程建立参考网格并自动登记训练样本。
支持种子复现、批量多工况、几何分组划分验证集、质量过滤、暂停续生成和历史 JSON 下载。
新增依赖见 `requirements-generator.txt`；完整使用方法、误差含义与上游参考说明见
[随机训练模型生成器](../docs/RANDOM_TRAINING_DATA.md)。

## 使用

1. **导入模型 JSON**：支持多文件，也可展开“从本机路径导入大文件”填写完整路径。
   模型应包含几何、材料、支撑、原始载荷，以及作为参考的计算节点和三角形单元。
   “加入当前自适应模型”读取结构绘制/计算页的当前场景。
2. 每个工况自动从纯几何生成约 400、1000、2000 节点预算的三种粗网格。
   参考网格仅提供目标尺寸，位移、应力和最终参考节点不会作为网络输入。
3. 勾选工况，设置轮数、学习率、宽度和层数，点击 **开始新训练**。
   验证样本需使用不同基础几何；相同几何的载荷变化会被归入同组，不能跨训练/验证划分。
4. **保存检查点**不停止训练；**保存并暂停**完成当前优化步、保存后暂停。
   等待状态显示“已暂停”后即可关闭程序。重新启动后，从记录列表选择任务，点击 **继续训练**。
5. 继续训练会保留原工况，并加入勾选的新工况；新工况从下一轮进入数据顺序。
   未完成的任务继续原定轮数，已完成的任务追加面板中设置的轮数。
6. 在结构绘制页准备新模型，返回训练页选择检查点并点击 **预测当前模型节点**。
   可下载预测 JSON，或点击 **应用预测网格**后在计算页求解。
   预测按尺寸场迭代细化，不需要中间有限元求解；目标误差是条件输入，**不是已验算的精度保证**。

材料弹性模量按原场景约定为 GPa，特征提取时转为 Pa。长度沿用当前模型单位，建议统一使用 m；
点载荷为 N，边界分布载荷为 N/m，体力输入为加速度 m/s²，结合材料密度计算。

## 统计口径与标签质量

新版训练在每轮优化结束后，用同一模型权重分别评估训练集和验证集，再按
“粗网格变体 → 工况 → 几何”逐级等权平均。优化梯度也按训练几何的工况数量均衡加权。
因此显示的训练损失不再是最后一个优化步的损失；旧轮次不重算，数据、用途或评估口径变化时曲线分段。

**自适应训练策略**默认启用。指标持续 8 轮不改善后，`ReduceLROnPlateau` 将学习率减半；
独立验证指标持续 25 轮无显著改善（默认绝对阈值 0.0001）、至少完成当前阶段 10 轮，
且已经尝试降学习率后会早停。轮数均可设置，早停等待轮数为 0 可关闭早停。
没有验证集或验证几何曾被该模型学过时，仅按训练指标调学习率，不自动早停。
验证几何少于 3 张时显示样本不足提示；诊断是风险提示，不能直接证明欠拟合或过拟合。
调度器、优化器、监控计数与随机状态一起保存，暂停后继续可恢复；修改数据或策略会重置监控阶段。
新训练使用 AdamW（默认 weight decay 0.0001），旧检查点保持原优化器参数。

**训练诊断与标签对照**显示基础粗网格不做预测时的标签损失、尺寸偏差因子、
预测比参考大于 1.25 倍及小于 0.8 倍的面积比例。尺寸偏差因子为平均绝对对数尺寸误差的指数，
不是有限元百分比误差。诊断会区分验证不足、历史训练泄漏、标签基线尚未超过、平台期和过拟合风险，
不会把“比参考更细”自动当成更好，也不会据此篡改标签。
预测自动优先采用当前记录的最佳验证检查点，续训自动采用最新检查点；手动指定版本仍优先生效。
要证明预测网格优于参考，仍需在相同几何和载荷下求解，比较实际 ZZ 误差及节点数，不能仅看标签损失。

策略依据：[PyTorch ReduceLROnPlateau](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ReduceLROnPlateau.html)。

- **独立工况数**：当前训练记录实际学习过的不同模型/载荷工况数。
- **累计学习次数**：一张粗网格参与一次优化计一次。一个工况的三种粗网格训练 50 轮，为 150 次。
- **累计处理单元**：每次优化参与的输入粗网格单元数累加，不是参考网格单元数。
- 曲线为每轮平均训练损失；面板当前训练损失为最近一个优化步。损失不等于 ZZ 相对误差。
- 有自适应历史时，以**实际达到的 ZZ 估计误差**作为尺寸标签的精度条件，并保留请求精度、停止原因。
  达到轮数或耗时上限不能冒充目标达标。
- 无有效 ZZ 历史时，使用面板人工指定的参考误差，并明确标注为假定值。
- 缺少验证集时不计算验证损失，不声称已证明对新几何的泛化能力。

## 模型与数据

- `model.py`：编码器 → 6 层残差消息传递（默认 64 维）→ 区域内空间池化的粗图传播 → 尺寸解码器。
  图节点对应三角形单元，共享边产生图连接。输出为归一化局部尺寸的对数。
- `graph_data.py`：23 维特征，包括位置、当前尺寸、材料、边界/支撑距离、载荷场和精度条件；
  边特征包括相对位置、长度、区域一致性和材料对比。参考尺寸按区域使用七点采样投影，
  目标是模仿局部密度，不要求节点编号或坐标逐一相同。
- `mesh-worker.cjs`：在隔离进程复用现有几何、约束布点及 Triangle 细化逻辑。
- `worker.py`：GPU / CPU 优化、样本登记、检查点、数据顺序和状态控制。
- `runtime_launcher.py`、`device_runtime.py`：隔离环境探测、真实训练自检、自动后端选择和 CPU 回退。
- `../training-bridge.js`、`../src/pages/training/dashboard.js`：本地 HTTP/进程接口及仪表盘。

方法参考：[AMBER 尺寸场学习论文](https://arxiv.org/abs/2406.14161)。这是面向本程序的独立实现，
没有复用其训练权重，也没有将论文中的性能结论作为本模型的性能结论。

## 训练工况预览与删除

已导入数据可直接更改用途：在每行点击 **改为训练集 / 改为验证集**，或勾选工况，
选择 **更改学习用途** 后点击 **应用到勾选工况**。同一几何的其他工况会同步移动，
生成历史中已分配的工况旁也提供相同的切换按钮。
不重新导入或重建粗网格，保留样本 ID、参考模型和已有检查点。训练和数据生成期间需先暂停再修改。
生成历史中的实际分配用途同步刷新；继续训练时会按当前用途重分组，并移除旧训练队列中的验证工况。
用途修改不会撤销模型过去学过的内容；已经用于训练的数据移入验证集后，不是该模型的独立泛化验证。

在“训练数据”列表点击工况名称或 **预览**，或重新勾选一个工况，即可查看该数据模型。
预览保留几何轮廓、孔洞、材料分区、固定支撑、点力、线载荷及体力；下拉框可切换
**几何、材料与载荷**、**参考网格**以及各张 **输入粗网格**。
预览读取工况自己的 `reference.json`，不修改结构绘制页的当前模型，不重新求解，也不读取 `graphs.pt` 张量。

每行的 **删除** 可删除单个工况；**全选工况**、**取消勾选** 和 **删除勾选工况** 支持批量管理。
勾选状态同时用于训练数据选择，批量删除前会列出工况名称、短 ID、文件数、占用空间和受影响的训练记录。
点击确认后直接永久删除 `storage/datasets/<工况ID>/` 整个目录，包括参考模型、训练图和元数据，
不移入回收目录。原始导入 JSON、自动生成批次中的源模型和结果文件、已有模型检查点保留。

如果工况被模型的任一历史检查点引用，确认框会明确提示：删除后无法完整恢复原任务的数据与读取进度，
也无法导出包含原数据的完整模型包。权重仍可预测，也可作为后续训练的初始参数；
当前“继续训练”入口按原任务恢复，要求原数据，目前尚无只使用当前数据从已有权重继续训练的独立入口。
检查点中的样本 ID 和历史统计不会被篡改。
需要恢复原训练时，应从包含原样本 ID 的完整备份恢复数据，重新导入原 JSON 会生成新的样本 ID。
删除前后端均重新检查任务状态、磁盘清单及训练记录；其他程序实例占用模型锁时拒绝删除。
删除期间发现文件或检查点变化，会要求重新打开清单确认。

预览接口为 `GET /api/training/dataset/<工况ID>/preview`；删除分两步调用
`POST /api/training/dataset-delete-impact` 与 `POST /api/training/delete-datasets`。
后者须提交前者返回的清单令牌；引用中的数据还须提交明确的 `allowReferenced: true`。

## 保存与恢复

仪表盘顶部的“模型与检查点管理”使用当前模型下拉框选择记录，短 ID 可区分同名模型。
支持重命名、删除、导入、导出和检查点管理。训练期间需先保存并暂停，再操作模型管理。

- **导出模型包**：打包所有可读检查点和它们依赖的样本，再点击“下载模型包”保存 ZIP。
- **导入已训练模型**：导入本程序的 ZIP 包时建立独立模型记录，不覆盖已有模型；
  完整 `.pt` 检查点也可导入，但其全部训练/验证样本必须已在本机。
  不支持只有裸网络权重、缺少优化器与训练状态的 PT 文件。上传限 512 MiB，解压内容限 1 GiB。
- **选择检查点**：表格列出步数、完成轮数、训练/验证损失、保存时间、文件大小及最新/最佳标记。
  自动选择最新可用检查点后，“继续训练”沿用当前模型；指定文件后，两个继续按钮均会
  **创建独立训练分支**，保留原模型及其后续进度。未完成的任务完成原计划，已完成的追加设置的轮数。
  预测也使用这里选定的检查点。
- **删除选中检查点**：保留至少一个可用检查点。删除最新文件时，显示进度回到剩余最新可用版本。
- **删除模型**：移除记录及其全部检查点，共享样本和已生成的预测保留。

删除前显示包含目标名称/文件名的确认框，确认后**永久删除磁盘文件**，不再移入回收目录。
删除模型也会移除完整模型目录。稳定的进程锁移至 `storage/locks/`，锁文件不是模型或检查点。

“存储清理”显示以下类别的项目数和大小，点击按钮并确认后永久清理：
- **删除暂存导出包**：删除 `storage/exports/` 内程序生成的 ZIP。
- **删除预测 JSON**：删除 `storage/predictions/` 内程序生成的 JSON，并清除仪表盘的预测预览和下载链接。
- **清理历史删除残留**：清理旧版本 `storage/trash/` 中已删除的模型/检查点，以及 `runs/` 中只有旧锁文件的空记录目录。

清理是全局的，不局限于当前选定模型；现存模型检查点、共享训练样本以及用户已下载到其他位置的副本不受影响。
训练过程中清理按钮禁用；后端同样检查训练状态与跨进程锁。

数据保存在 `python_machine_learning/storage/`，已加入 `.gitignore`：

```text
storage/
  datasets/<工况ID>/metadata.json    工况用途、精度、分组和参考规模
                   graphs.pt        训练图张量
                   reference.json   精简几何、参考网格和粗网格
  runs/<训练ID>/metadata.json        最近状态、统计、曲线
                checkpoint-metadata.json  已成功保存的状态
                checkpoint-*.pt     版本化模型与训练状态
  predictions/<预测ID>.json         可导入现有程序的预测场景
```

检查点包含网络参数、AdamW 状态、训练配置、样本清单、当前轮顺序和游标、累计统计，
以及 Python/NumPy/PyTorch/CUDA 随机状态。新检查点中的模型和优化器张量统一保存到 CPU，可跨设备读取续训。
跨后端、版本或不同显卡续训不保证逐位一致；GPU 随机状态仅在兼容后端恢复。
当前使用 float32 和固定学习率，不使用需要另存状态的学习率调度器或混合精度缩放器。
恢复时保留未完成轮的数据顺序；新工况和旧工况共同训练。

默认每 60 秒自动保存，手动保存、暂停、完成也会保存；验证指标改善时保留最佳检查点。
使用临时文件、落盘和重命名，每次检查点使用新文件名，以减少 OneDrive 文件占用的影响。
保留最近三份完整版本及最佳验证版本；读取失败时尝试上一份，暂时被同步程序占用的旧版本延后清理。
同一训练记录有进程锁，避免不同程序实例同时继续写入。

异常断电恢复到最近成功检查点；最近检查点之后尚未保存的优化步不能保证保留。
移动到另一台机器时，应一起备份整个 `storage`，包括对应 `datasets`，不能只复制权重。

## 本次接入验证

- GPU：RTX 4070 Laptop，PyTorch 2.14.1+cu130。
- 已导入 `1型裂纹扩展.json`：参考 22,108 节点、43,688 单元，实际 ZZ 误差约 3.88%，停止原因为细化轮数上限。
- 输入粗网格为 810、1746、3228 单元；七点标签投影没有使用最近质心回退。
- “裂纹模型接入试训”已完成 50 轮 / 150 步 / 150 次图学习，累计处理 289,200 个输入单元。
- 第 112 步曾保存并暂停，重启服务后恢复至第 150 步，检查点保留于上述训练目录。
- 第 112 步的预测测试生成 14,308 节点 / 28,008 单元，达到 20,000 节点预算保护前保留上一张完整网格。
  该网格经现有 C++ 求解器验算，ZZ 估计误差为 **7.19%**，没有达到当时设置的 3.88% 目标。
  该结果用于验证端到端流程，不能证明预测精度达标或对新模型有效。

当前仅一个独立训练工况，没有独立验证集。下一阶段应补充不同几何、裂纹/孔洞尺寸、支撑、
材料和载荷组合，按基础几何划分数据，考察实际误差、节点预算及总耗时。
当前输出为二维 TRI3 各向同性尺寸场，尚未实现网格粗化、方向性尺寸场、三维或误差认证。
